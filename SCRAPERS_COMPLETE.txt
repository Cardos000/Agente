🎯 KEY PRINCIPLES IMPLEMENTED

1. DEFENSIVE EXTRACTION
   ✅ All fields are Optional (can be None)
   ✅ Missing data → None, NOT skip
   ✅ Parse error → log & continue
   ✅ Never discard listing

2. NO BUSINESS LOGIC
   ✅ Extract price as RAW string ("150000" or "150 000 €")
   ✅ Extract area as RAW string ("95 m²" or "95")
   ✅ Extract location as RAW string ("Porto")
   ✅ NO filtering, NO validation, NO interpretation
   ❌ Don't filter by price range
   ❌ Don't check area minimum
   ❌ Don't validate transport
   ❌ Don't apply profile rules

3. INDEPENDENT OPERATION
   ✅ Each scraper can run standalone
   ✅ Each scraper can fail without affecting others
   ✅ Orchestrator combines results
   ✅ Can run subset of scrapers

4. TRANSPARENT LOGGING
   ✅ Pages fetched logged
   ✅ Listings found logged
   ✅ Errors encountered logged
   ✅ Statistics per scraper
   ✅ Total time measured

5. ANTI-BOT EVASION
   ✅ Random user agents
   ✅ Random viewports
   ✅ Random delays (2-5s configurable)
   ✅ Stealth mode enabled
   ✅ Proper headers/localization

🎓 DESIGN DECISIONS

Q: Why extract RAW data instead of cleaned?
A: Separation of concerns. Scrapers are INPUT. Analysis agents handle
   interpretation. This allows easy changes without rebuilding scrapers.

Q: Why not filter in scrapers?
A: Because you might change your mind about filters. Better to have raw
   data and apply filters in dedicated agents.

Q: Why continue on error?
A: Better 150 good listings than 0 because 1 failed. Philosophy:
   "Prefer to show more than lose an opportunity"

Q: Why defensive extraction (None instead of "N/A")?
A: For later agents to distinguish "missing" from "present but empty"
   and make intelligent decisions about confidence.

Q: Why multiple scrapers instead of one API?
A: No single API covers all Portuguese real estate. Multiple sources
   = more comprehensive coverage. Redundancy helps (if one fails).
